01Three things to know first

Each of these will shape a redesign more than any individual screen will, and none of them is visible from the documentation.

Docs are wrong

The README describes a different app

It documents danfo orange #E8541A, a warm-white ground and DM Sans. The code ships danfo yellow #F5C518, a near-black forest ground and Plus Jakarta Sans. Trust theme/colors.ts, not the docs.

Half-migrated

Dark mode only reaches half the app

17 files read the live theme through useAppTheme(). 13 files — including six screens — import the static Colors, which is hardwired to the dark palette. Those screens stay dark whatever the user picks.

No scale

Spacing and radius are ad hoc

There is a color file and a type file, but no spacing or radius tokens. Twelve distinct corner radii are in use, including 19, 9, 3 and 2. Nothing enforces a rhythm.

02Color

Defined in src/theme/colors.ts as two complete sets, WW_LIGHT and WW_DARK. The brand accents are deliberately identical in both — only the neutral canvas flips. That's a sound decision worth keeping.

03Transport mode colors

The most distinctive thing in the system: each mode of Lagos transport carries its own colour and its own text colour, so a route leg is legible at a glance before any label is read. Identical across light and dark.

Ferry tokens are still defined, but ferry routes were removed from the routing engine in commit 76ca3e7. Dead tokens — decide whether ferry is coming back before designing around them.

Keke green and the brand success green are the same value, so a keke leg and an "arrived" state read identically. Worth separating in a redesign.

04Type

Weights available: 300 Light · 400 Regular · 500 Medium · 600 SemiBold · 700 Bold · 800 ExtraBold. The Typography object only exposes 400–700, so the loaded 300 and 800 faces are shipped but unreachable through tokens.

05Space and radius

Neither has a token file. These are the values the screens actually use, counted across src/screens.

Padding — a 16 rhythm with a 14 fighting it

16 appears 26 times, 14 appears 21 times, then 8 (13), 20 (9), 12 (8), and a scatter of 3, 4, 10, 24, 32. A 4-point scale of 4 / 8 / 12 / 16 / 24 / 32 would absorb almost all of it; the 14s are the single biggest source of misalignment.

09Where a redesign should start

Ordered by how much each one unblocks the rest. The first two are structural — doing them first means the later visual work only has to be done once.

01

Finish the theme migration

Move the 13 files still importing static Colors onto useAppTheme(). Until this is done, any palette change only lands on half the app, and the dark mode toggle stays broken for six screens.

structural
02

Add spacing and radius tokens

A theme/spacing.ts with a 4-point scale and a radius set of 10 / 12 / 16 / 20 / 999. Do it before restyling, so the restyle applies tokens rather than baking in new one-off numbers.

structural
03

Split keke green from success green

Both are #5DBB63, so a keke leg and an arrival state are indistinguishable. Give the transport modes their own ramp, separate from semantic state.

palette
04

Give warning its own value

warning is currently the same yellow as the primary action, so a caution and a call-to-action look alike. Also decide whether ferry stays — its tokens outlived its routes.

palette
05

Rename the token that isn't orange

orange, orangeGlow and orangeDim all hold yellows. Every future reader will trip on it, and it is the reason the README documents the wrong brand colour.

naming
06

Resolve the duplicate RouteStepCard

Two files, both live, one theme-aware and one not. Pick the survivor before restyling either.

cleanup
07

Reconsider Home's load

At 1245 lines it holds a map, a search overlay, an alerts feed and a routes rail, and it is the only entry point to every other screen. With no tab bar, Navigation sits four pushes from launch. A bottom tab bar is the obvious structural question a redesign should answer.
